# E6a — Mobile: Insights and Wallets screens (2026-11-16)

**Delivered (Expo app `oneledger-mobile`, entered from More → Insights / Wallets):**
- **Insights** (`/insights`): period chips (This month / Last month / Last 30 days — whole Africa/Kigali days, end exclusive), wallet chips (All wallets + each wallet; filters the whole screen), per currency: Money in / Money out / Net, a plain-words comparison with the previous period ("No earlier period to compare with" when there is none — never a fake change), a "Where it went" list with percentage **text and** a bar, people & merchants, plus honest notes: cash withdrawals ("money you took out, not necessarily spent"), transfers between your own wallets (excluded, with a link to see them), pending (not counted yet, with a link), unsupported currencies, and the freshness time. Every number opens **Insights detail** (`/insights-detail`): the transactions behind it, built server-side with the same rules as the total.
- **Wallets** (`/wallets`): each wallet with its balance **and** a label — Confirmed / Estimated / Out of date / Not available — what that label means, the as-of time and the reasons; **"I checked my balance"** records a balance you type (via the audited RPC `record_manual_balance_observation`, no new endpoint). A balance you type is shown as an estimate, never "Confirmed". "Not available" never shows a number.
- Plumbing: API client functions (`fetchInsights`, `fetchDrilldown`, `fetchWallets`), strict response parsers (amounts as `bigint` from decimal strings; a malformed currency block or a status/number contradiction is refused, not half-shown), `Chip` design-system component (selected state is bold text + fill + announced to screen readers), period/format helpers.

**Verified:** `npm run typecheck`, `expo lint`, `jest` (**165 pass**, 25 new: parsers incl. >2^53 precision and malformed/contradictory payloads, comparison wording, bps formatting, Kigali period boundaries incl. year wrap and near-midnight, balance-input parsing that never silently rounds), and `expo export --platform web` (bundles all routes).
**NOT verified:** **no screen was run** — not on a phone, an emulator, nor in a browser; the screens need a signed-in session against the web API with the 3.0 flags on, which I couldn't provide. So layout, touch targets, text scaling, dark mode, screen-reader order, and the real API round trip are untested. The endpoints themselves were only stub-tested (#211). **Do a hands-on pass on a real iPhone and Android phone before enabling anything.**

**Dependencies:** both screens need `MOBILE_API_ENABLED`, `INSIGHTS_CENTER_ENABLED` / `BALANCE_PROVENANCE_ENABLED` on the web (each answers 404 → the app shows "isn't available yet" and no retry button).
**Known gaps:** the selected wallet isn't remembered between visits and doesn't yet filter the Home/Transactions tabs (only Insights); no charts (lists + bars only, by design); no pull-to-refresh on these screens (screens re-load on focus); the Insights "People and merchants" card isn't tappable until the people screens (E6b) exist; Release blocker unchanged: mobile store release still needs approved brand assets, real-device sign-off and the Apple account.
